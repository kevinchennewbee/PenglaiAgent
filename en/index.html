Origin

A non-coder and his AI butler

I spent a decade in network engineering, security, and ops — but I couldn't write code. Not a line. Every line in this repository was spoken, sentence by sentence, through AI coding tools. Penglai itself is the proof of what it wants to show: in the AI era, ordinary people can build tools for themselves.

0.3 proved the narrative: move the agent into the chat apps you already use, and keep every byte of data on your own machine. But in the Python era, auditable approvals were still "right direction, half-built implementation." 0.4 is a serious rewrite — TypeScript, strongly-typed protocols, and the open-source Pi kernel — turning spoken ideas into kernel-level capabilities.

Penglai is the mythical island mountain in the Records of the Grand Historian — everyone has heard of it, almost nobody has set foot on it. Today's AI is to ordinary people what Penglai was to the ancients; APIs, terminals, and config files are the fog on the sea. We want to bring the immortal mountain into your chat window: no navigation to learn — if you can send a message, you can reach the island. As the legend goes, "eight immortals cross the sea, each showing their own powers" — many models, many channels, each in its own way, all serving the same you.

— the author of Penglai, after the 0.4 rewrite
One surface

Same assistant; projects only tighten its boundary

There is no "lite mode." The assistant you chat with in the terminal is the same one that writes files in a trusted project — tools, budgets, and approvals never change with the label; only the boundary does.

浮动FLOATING

Anchored at its own ground (memory and drafts): questions, drafts, thinking out loud.

  • Chats with you, answers questions, reads files — streaming turns, instant replies
  • When the conversation turns to changing project files, it proposes anchoring instead of acting on its own
  • The full toolset is always in its hands; what stops it is approval and the jail, not a "mode"
项目锚定ANCHORED

Anchored to a project directory you explicitly trust: long autonomous loops, fully inside the project jail.

  • Writes code, runs commands, edits files — all inside the realpath-checked jail
  • Anchoring ≠ trust: work starts only with your nod; key operations are approvable and revertible
  • On completion it self-reviews, records evidence and cost, and can cite the artifacts back in the conversation

A permission dial (plan → confirm → auto-edit → full) tunes how often you are asked; the four-level ladder is one backbone

Why Penglai

Three things others can't give you

其一 · I

Presence

Living inside your IM

No new app to install, no terminal to babysit. It lives in your Feishu — one message away on your commute or your lunch break. The next stop for agents isn't the IDE; it's the chat window you already open every day.

其二 · II

Sovereignty

Persistent data is self-hosted on your machine

Chats, memory, abilities and credentials are persisted on your hardware; logs are redacted before disk and none of this ships in a distribution. A call to your chosen BYOK model sends the prompt and context needed for that task to its endpoint.

其三 · III

Evolution

A skill tree rooted locally

Every finished task is automatically reviewed, distilled into an SOP, and admitted to the skill tree only after an audit. The next similar job runs faster and steadier — it grows stronger on your machine, not pricier.

Capabilities

What 0.4 actually does

Every item below is covered by the current 0.4.1 code and real acceptance runs — this is not a roadmap.

Personal context New in 0.4.1

Grant one local documents folder; Penglai builds a deletable derived index on your machine with SQLite + FTS5 — original files and the complete index stay local, originals are never modified, and access is revocable any time. When a cloud model answers, the relevant snippets retrieved for that request are sent to the model provider you selected. Chats and tasks retrieve automatically, and answers carry Host-verified source cards: which file, which section, and whether it has gone stale — kept truthful across restarts. Useful from minute one: hand over a folder in the wizard and an empty chat offers example questions generated from your real document titles.

Full penglai CLI

Run it bare and chat; a first-run wizard wires up your model. doctor, status, migrate — one command each. doctor --export creates a redacted support bundle that excludes credentials and product state.

Documents and the public Web

Import and read PDF, Word, Excel and PowerPoint; create standard PDF, DOCX, XLSX and PPTX deliverables; preview common document and code artifacts as read-only text inside Desktop; search and fetch real public pages with source links. Every network call asks you first.

Four-tier approvals

L1 autonomous / L2 one-click / L3 mandatory confirm + trace / L4 refuse — fully logged and replayable.

Feishu channel

Chat, kick-off, progress, and approval cards — the full workflow closes the loop inside the IM.

Skills and MCP ecosystem

Install, verify, enable and remove local/GitHub Agent Skills. MCP is manual-connect only, never auto-started, and every tool call requires fresh L3 approval. Distilled SOPs still enter through audit.

Cost circuit breaker

A visible usage ledger; when the budget trips, it breaks first and asks later — never silently burns.

Local voice

SenseVoice ASR plus the complete MOSS-TTS-Nano ONNX CPU pipeline; Desktop recording and per-message playback stay local.

Active companionship

Off by default. Choose quiet, present, or active; morning/evening opportunities and emotion follow-ups still use the same EpisodeRunner.

One-command 0.3 → 0.4 migration

Memory, model profiles, and identity come over from 0.3 in a single command.

Desktop evidence rail

Safe Markdown, ordinary-file inbox, full searchable history and completion notifications; jailed evidence artifacts preview, open or reveal in Finder, with every fact grounded in observation.

Approvals

The nod happens in the chat

Operations that change external state — pushes, publishes, destructive edits — require your confirmation under the four-tier policy. Approval cards land right in the Feishu conversation: level, action, reason, task at a glance, approve or reject in one tap.

Who asked, who decided, and when — all logged and replayable. Buttons optional: replying "approve b3f1c9a2" works just the same.

Architecture

One core, three classes of thin clients

The headless Host is the only product core. CLI, Desktop, Feishu, and WeChat are thin clients — every fact comes from the Host; clients hold no product state.

0.3 ran on GenericAgent (with gratitude — the "genes"); in the 0.4 rewrite, Pi is the engine and the Host is the product.

Security & privacy

Deterministic guardrails, not model self-awareness

Data sovereignty

  • Self-hosted by defaultAPI keys, chat history, long-term memory and channel credentials are persisted locally; model calls send only the prompt and context needed for the current task.
  • Auditable approvalsFor every tier: who asked, who decided, and when — all logged and replayable.
  • Injection defensesDocument, web and MCP results are wrapped as untrusted data; fake system or owner instructions inside them have no authority, and sensitive actions still pass deterministic approval.
  • Voice stays localSenseVoice ASR + MOSS-TTS-Nano run entirely on your CPU — voice data never leaves the machine.

BYOK · bring your own key

  • Built-in 11-vendor catalogThe setup wizard live-tests each step; keys are stored in a 0600 private file on your machine.
  • OpenAI-compatible endpointsPublic gateways require HTTPS; plain HTTP is restricted to exact localhost / 127.0.0.1 / ::1.
