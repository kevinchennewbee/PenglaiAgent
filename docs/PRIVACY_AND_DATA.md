# Privacy and local data — Penglai 0.4

Penglai 0.4 has no Penglai account service, advertising SDK or product
telemetry endpoint. Product state is local by default. This does not mean the
application is offline: when the Owner configures a model provider, web
research, a remote MCP server, Feishu or WeChat, the requested content is sent
to that selected third party under its own privacy terms.

## What is stored

The default data root is `~/.penglai` (or `PENGLAI_DATA_DIR`):

| Data | Location | Purpose |
| --- | --- | --- |
| Host credential | `host.token` | Authenticates loopback Host calls; current-user regular file, 0600 |
| Model profiles and keys | `profiles.json` | Provider, model and optional API key; 0600 |
| Product facts | `product.db` | Project, Task, Run, Step, Evidence, Approval, budget and usage records |
| Conversations and goals | `conversations/<id>/` | Transcript JSONL, goal state/history and conversation-local state |
| Global memory and identity | `memory/global/` | Owner-approved durable notes, identity and SOP receipts |
| Installed Skills | `skills/` | Skill content, enable state and integrity receipts |
| MCP configuration | `mcp.json` | Owner-configured server commands/endpoints; may include headers or environment references |
| Channel configuration | channel configuration files | Feishu/WeChat routing, allowlists and credentials configured by the Owner |
| Voice models | `models/` | Optional locally downloaded ASR/TTS weights |
| Logs and diagnostics | `logs/`, `diagnostics/` | Bounded operational logs and Owner-triggered redacted support archives |
| Update recovery | `update-backups/`, update journal | Database backup and recovery state around updates |

Anchored projects may also contain `.penglai/memory/` and
`.penglai/inbox/`. Generated PDFs, office files, source changes and other
deliverables remain in the Owner-selected workspace.

## What leaves the computer

- Prompts, selected context and tool results sent to the configured model API.
- Search terms and fetched public URLs when the Owner approves web research.
- MCP arguments sent to an Owner-connected remote MCP endpoint; stdio MCP runs
  locally but is still third-party code.
- Messages and attachments routed through enabled Feishu/WeChat services.
- Skill archives fetched from an Owner-selected GitHub URL during installation.
- Version/update requests to the canonical GitHub Release endpoints.

Penglai does not add its own analytics event to these exchanges. Provider and
channel services may log data independently.

## Retention and deletion

There is no automatic cloud retention because Penglai operates no product
cloud. Local conversations, Evidence and recovery data remain until the Owner
deletes them or removes the data directory. Current 0.4 does not provide a
separate automatic retention timer.

Uninstalling the app does not silently delete `~/.penglai`, so reinstalling can
recover the same assistant state. To erase local Penglai state, first make any
desired backup, quit Penglai, remove the application, then explicitly remove
the configured data root and any project-local `.penglai/` directories or
generated deliverables. Revoke provider/channel tokens separately if they may
have been exposed. See [`UNINSTALL.md`](UNINSTALL.md).

Diagnostic ZIP files are ordinary local files chosen/generated by the Owner;
delete any copies after support use. They exclude product state by design and
redact credential-shaped text, but redaction is best-effort.
