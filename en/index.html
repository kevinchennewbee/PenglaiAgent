Purpose

If DSH is like Linux, Penglai aims to be an approachable distribution layer

Penglai does not rebuild an agent and is not merely a skin. It respects DSH's “everything is a plugin” philosophy: package installation, first-run setup and practical combinations so ordinary people can truly use DSH.

Version 0.5.0 was the full reconstruction: Agent, Workspace, Session, Turn, models, tools and the base Web UI returned to official DSH. Version 0.5.1 brought that decision to three platforms. Version 0.5.3 closes the defects found by real upgrade drills while keeping official DSH 0.1.1-rc.1 fixed at the center.

Plugin Center is now a real path for growth. Reviewed DSH plugins enter a Penglai-signed, immutable GitHub Release catalog; users refresh, download, confirm permissions and enable them without reinstalling the desktop client for every new plugin.

Penglai plugins

One plus one becomes more than two

Each ability respects DSH boundaries. Their composition is where Penglai becomes distinctive.

Plugin Center

Manages plugins from real DSH loader inventory and reads public signed catalog 4. Office Reader 0.1.2 has passed signature verification, disabled-first installation, owner permission confirmation, post-update DSH restart and real document extraction. Arbitrary npm, Git and URL installation remain closed.

IM connections

Private Weixin and Feishu conversations flow through a durable claim, an official DSH Turn, and back to the original channel. The scanner is the default sole identity.

Local ASR

Downloads SenseVoice on demand with visible progress. Encrypted Weixin SILK is decoded and transcribed locally; language and emotion remain internal auxiliary context.

MOSS-TTS-Nano

Installs the local model on demand and speaks exact durable DSH finals. Feishu uses native audio; Weixin currently receives reliable playable audio.

Personal context

Indexes only directories you explicitly grant, using a deletable local SQLite FTS5 derivative index without modifying source files.

Layered memory

Separates global, Workspace and session-candidate memory. Long-term changes and SOPs require a visible diff and your confirmation; SOPs use official DSH Skills.

Token budget

Consumes official TokenMeter and routes. When prices are not trustworthy it reports tokens only; hard limits stop a new Turn before invocation.

Companion

Off by default. Reuses official Schedule, Session and Turn under quiet hours, daily caps, exact bindings and a no-unattended-tools gate.

Architecture

DSH at the center; Penglai makes the surrounding experience coherent

CORE

DeepSeek Harness

The sole Agent and UI core

Models, workspaces, sessions, tools, approvals, permissions, base Web UI and plugin runtime all come from official DSH.

DISTRO

Penglai desktop distribution

Install, onboard, brand, lifecycle

Embeds the target Node, Electron, pinned DSH closure and licenses. It never depends on PATH, global packages or first-run installation of the core.

ECOSYSTEM

Standard plugins

Optional, composable, removable

First-party plugins use official DSH services, slots, Remote and loader seams. They do not create a second Agent or chat system.

Pinned to official DSH 0.1.1-rc.1. Penglai 0.5.3 contains none of the former Pi/Host product line and runs no second Agent beside DSH.

Privacy and security

Local-first, without pretending the boundary is magic

What stays local

  • API keys and channel secrets use the official DSH credentials seam; renderer code never reads plaintext.
  • macOS credential directories/files use 0700/0600 and atomic writes. A privileged process under the same OS user may still read them — this is an explicit boundary.
  • ASR, TTS, indexes, memory, budget ledgers and companion schedules are separately inspectable and deletable. Workspaces and granted source folders are never application deletion targets.
  • No cloud account, sync or telemetry.

Network, updates and trust

  • Calling your chosen cloud model sends the prompt and context needed for that request to its provider.
  • Voice models download on demand from pinned sources with integrity checks; first boot never installs the core from the network.
  • macOS packages are ad-hoc sealed without Developer ID or notarization. Windows has no Authenticode signature and may show a system warning.
  • 0.5.0 requires a manual same-platform overlay. A completed 0.5.1 profile can use the signed updater; if the 0.5.1 Workspace gate keeps Settings out of reach, install the same-platform 0.5.3 package manually. Both paths preserve 0.5-generation data and require explicit user action.
