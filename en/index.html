What actually changed

DSH is still the only core. Penglai makes it a complete desktop product.

Official DSH owns models, tools, Workspace, Session, Turn, and the conversation interface. Penglai takes care of the unglamorous details that decide whether normal people can use it: installation, first-run setup, local paths, process supervision, plugin lifecycle, updates, and data removal. In 0.5.5, Office and Memory become useful from the first launch.

Already in the installer

Office and Memory start on. Everything else waits for you.

Penglai Office

Inspect, create, edit, preview, and save DOCX, XLSX, PPTX, and PDF. Writes have a plan and confirmation. PDF output includes a Chinese font. LibreOffice is not a user dependency.

Penglai Memory

Personal facts can be shared deliberately; project work stays in its official Workspace. Memories have provenance, can be corrected or forgotten, and can be explored as a graph.

First launch should not be a roadblock

Seven steps, complete only after the first real reply.

Choose language and appearance, read the local-data boundary, select a provider and model from the official catalog, test your own API key, choose a real Workspace, then send the first DSH message. You can go back, retry, and resume after restart. A failed request is never dressed up as success.

Why Penglai

I spent more than ten years around networking, security, and operations, but I was not a software developer. Penglai began with one stubborn idea: in the age of AI, ordinary people should be able to build tools for themselves.

Computers travelled from command lines to windows and then into everyone's pocket. Agents should make the same trip. If I can send a message, I should be able to reach my own assistant. If it acts for me, I should be able to see what it was allowed to do, what actually happened, and what it cost.

Penglai has been rebuilt more than once. The important decision in 0.5 was to stop building another agent and stand on DeepSeek Harness instead, then do installation, Office, Memory, messaging, and local voice properly. Older generations remain in Git history because they explain the journey; their runtimes are not mixed into the new DSH core.

The boundary, plainly

A community distribution, without pretending its signature is an OS endorsement.

No Penglai account. There is no telemetry service or cloud memory sync. Model calls still send the context needed for that task to the provider you selected.

macOS is not notarized. The DMGs are ad-hoc signed; Windows has no Authenticode. Gatekeeper or SmartScreen may warn.

Plugins are not a sandbox. Signatures, hashes, permissions, and rollback protect distribution, but DSH plugins still share the local DSH process.
